## Why

Facts are generated by a model, so checking the model's submitted number against its source is essential. The current word matcher treats punctuation as a boundary: a decimal's integer part or an unsigned fragment of a signed quantity can pass. The submitted unit is compared with the registered metric, but not verified against the quoted source; relabeling a source unit can pass too. The existing requirement is “exactly as written”, not conversion or inference.

## Current state and conventions

`internal/importer/facts.go:209` accepts a match when adjacent characters are not word characters; `isWordChar` covers letters, numbers, marks and underscore, not decimal/sign punctuation. `parseValue` returns the submitted number text and unit. `checkStatic` at line 435 ignores that returned unit:

```go
marker := m.Unit == "" && (num == 0 || num == 1)
if !marker && wholeIndex(q, numText) < 0 {
    bad(i, "the value %s is not in the quote as a whole number", numText)
}
```

`internal/importer/apply.go:191` compares submitted unit with the metric's unit. `wholeIndex` also serves names and quotes: do not globally change its semantics to fix numeric matching. `inspect.go` already has a CommonMark/GFM table parser and CSV support. The [import guide](../guides/importing.md) permits a unit apart from the number and a unitless 0/1 result-word exception. Use `setup`, `fixture.metrics`, `fixture.facts` and `TestReadingsKeysAndReplay` in `importer_test.go`.
