# Explicit non-goals and deferred work

Researched, considered, and **deliberately cut** — recorded so they are not silently
re-added, each with the trigger that should reopen the question.

| Cut item | Why cut | Reopen when |
|---|---|---|
| Copies of the database that merge (sync, CRDTs) | Other devices are clients of the one writer ([D3](../decisions/D03-integer-ids.md)); a merge would force UUID keys and drop the checked FKs and the unique `name_key` [R75](../research/references.md#r75) | Never while the schema rests on those constraints |
| An entity `uid` (UUIDv7) | An integer id is never reused and owned names retain their identity, so references are already stable; `entities.import_key` covers an offline replay; the column is additive ([D3](../decisions/D03-integer-ids.md), executed) | A reference that must survive a re-key or a merge |
| Keeping or managing a file's original (a `media/` folder, the original as a BLOB) | A file is kept as its text and a small JPEG; the original stays where it is or is deleted once its text is kept ([D9](../decisions/D09-binary-files.md)): `life.db` stays the one thing to keep, and a lifetime of originals (hundreds of GB) never passes through a snapshot | An original with no other home that its text and preview cannot stand for |
| A video clip, a picture of every page of a document | A video keeps one frame and its transcript; a document its text and at most one picture ([D9](../decisions/D09-binary-files.md)). Additive: a table of further pictures per file | A real file that one frame or one picture cannot stand for |
| Broader recurrence and calendar synchronization | [Anchored tasks](../contract/planning.md) cover single calendar cadences; completion-relative intervals, multiple weekdays, timed appointments and external calendar reconciliation need distinct rules | A concrete task or calendar source that the bounded profile cannot represent |
| Project workflows, hierarchy and task dependencies | Ordinary pages provide project context; independent tasks and occurrences preserve intent and outcomes ([D23](../decisions/D23-no-tasks.md)) | A real question about project state or ordering that grouping cannot answer |
| Notification delivery state and device routing | [Reminder intent](../contract/planning.md) survives independently of delivery; providers, credentials, retries and phone actions belong to later application work | A chosen delivery path with concrete retry and acknowledgement requirements |
| Database encryption | Deliberate plaintext ([D17](../decisions/D17-contract-as-data.md)); protect the disk instead (full-disk encryption) | A legal/privacy requirement for at-rest encryption |
| Revision/history tables | Tombstones and append-only facts cover the need ([D12](../decisions/D12-no-revision-tables.md)); `sqlite-history` triggers are the documented fallback [R48](../research/references.md#r48) | Demonstrated need for intra-day history of structured rows |
| Raw wearable-import tier | health-mcp's two-tier mirror exists for provider quirks [R8](../research/references.md#r8); premature with zero importers | A second data source appears, or re-import fidelity bites |
| LOINC / UCUM / reference ranges | Interop vocabulary, not storage need ([D7](../decisions/D07-measurements.md)) [R8](../research/references.md#r8) | FHIR export or clinical data exchange wanted |
| Multi-resolution rollups | ~5 GB/lifetime of sensor data queries fine raw ([D7](../decisions/D07-measurements.md)) [R45](../research/references.md#r45) | Query latency is ever noticeable |
| Text-valued measurements | `value REAL` keeps charting trivial ([D7](../decisions/D07-measurements.md)) | A real series needs non-numeric values (then: probably a note + link instead) |
| JSON columns / property bags | The core anti-decision ([D2](../decisions/D02-typed-strict-tables.md)) | Never |
| Generic view system, AI generation | Cut from product scope by the owner. A model that reads a source for an import's facts, driven by the writer and checked against the source, generates nothing ([RFC 0010](../rfcs/0010-the-writer-drives-a-local-model.md)) | Product decision, not schema |
| Markdown export of the prose; an off-box copy; a CSV dump; continuous replication | Nothing in the schema depends on any of them ([D4](../decisions/D04-database-is-canonical.md), [D12](../decisions/D12-no-revision-tables.md)). The second copy of `life.db` is a dated snapshot with its restore check ([D25](../decisions/D25-snapshots.md)); the file itself is the thing to leave with, and taking a snapshot off the machine is the owner's business | A need a snapshot cannot meet: the prose read without SQLite, or a copy kept elsewhere by the application itself |
| Trash UI with restore/expiry | Tombstones ([D11](../decisions/D11-tombstones.md)) are already the data layer | UI work; zero schema change |
| `.sqlar` single-artifact packaging | `tar` covers "one file to email" | Frequent whole-archive portability need |
| An NFKC name key (`NFKC(casefold(NFKC(title)))`) | Unicode's formal case-fold promise covers NFKC text [R74](../research/references.md#r74); the NFC key is outside it only for titles with compatibility characters, rare in this life log. The key is derived, so switching is a recompute; two titles it merges (`Ｃａｆé`, `Café`) require explicit collision resolution before any recompute | A recomputed name key differs from the stored one after a Unicode upgrade, or a look-alike duplicate page appears |
| Unicode collation for titles (ICU / app-registered) | A collation only one program registers makes the DB unwritable and un-integrity-checkable for everyone else; the app-computed `name_key` gives the same uniqueness ([D5](../decisions/D05-pages-and-day-pages.md)) | Never, unless SQLite ships Unicode folding in the core |
| Hard deletes / GDPR-style erasure | Tombstones keep everything ([D11](../decisions/D11-tombstones.md)) | A legal/privacy need to truly destroy specific rows |
| Storing account numbers, IBANs, credentials | A plaintext DB makes them a liability ([D17](../decisions/D17-contract-as-data.md)) | Never in `life.db`; use a password manager |
| Partial dates (`1870`, `1870-05`) for people | Nothing asked for one yet. The standard for them is EDTF, now ISO 8601-2 [R70](../research/references.md#r70). The path is one migration: `DROP CONSTRAINT people_birth_day` and `ADD CONSTRAINT people_birth_day` with a CHECK that also accepts the EDTF forms wanted — executed for `YYYY` and `YYYY-MM` on a populated table; junk and month 13 stay rejected. Queries that do date arithmetic on `birth_day` must then skip partial values | The first ancestor or approximate date you want to record |
| Searching *inside* a CJK run | `unicode61`, kept, folds `é ü ș ț` but a CJK run is one token (`本語` does not find `日本語のノート`). The index is derived, so switching is one transaction — drop `entities_fts`, create it with `tokenize='trigram remove_diacritics 1'`, `rebuild` — and the sync triggers keep working (executed). Trigram finds 3+-character parts and still not two-character words (`京都`) | The first real CJK page you cannot find |
| Money: holdings, balances, net worth over time; then a transaction ledger, quantity × price, exchange rates, joint holdings | The first real import kept money notes as text; nothing has needed them as rows ([D18](../decisions/D18-money.md)); design kept in [D18](../decisions/D18-money.md), each later step additive on top of balances | The first balance or statement the owner wants stored as a number |
| A location track: a GPS fix per row | The owner does not want minute-by-minute tracking: a place has a point and a photo's place links its day, but no position is kept ([D16](../decisions/D16-places.md), [D21](../decisions/D21-location-history.md)); design kept in [D21](../decisions/D21-location-history.md) | A question that needs the moment: "where was I at 15:00 on that day?" |
| A photo archive: a library's photos, or their places, taken wholesale | `life.db` keeps the few photos that represent a day, chosen by the owner in any tool; only they are kept and only they give a place ([D9](../decisions/D09-binary-files.md), [D21](../decisions/D21-location-history.md)). The library stays in the photo tool | A question that needs the places of photos not kept |
| The zone of the device that wrote each row; a nickname | Timed readings carry `measurements.tz`; sessions retain explicitly supplied [unverified endpoint claims](../contract/session-time.md), never inferred device history. A nickname is the person's page text ([D10](../decisions/D10-time-model.md)) | A question that needs one |
| A habit's target ("three times a week") | A period says when a habit applies; completion is counted per day ([D24](../decisions/D24-habits.md)). Additive: a nullable column on `habit_periods` | A habit whose goal is not "every day" and a question about meeting it |
| Generic events, attendance and planned appointments | Recorded named periods answer structured span questions ([D22](../decisions/D22-events.md)); ordinary outings remain journal prose and links, not duplicated event rows | A distinct question or source that the bounded recorded model cannot answer |
